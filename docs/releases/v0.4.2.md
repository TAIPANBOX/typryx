# Typryx 0.4.2

A patch release for the wardryx proxy: it forwards the enforcement point's key only to the wardryx it is configured to reach. The `typryx` image, `ghcr.io/taipanbox/typryx`, is signed in the legacy `.sig` format that the cluster admission controller (policy-controller v0.15.1) reads, so the signature is verifiable there. Its reader takes only that tag, and before this release the image signature was not. cosign stays at v3.1.3, and the release workflow's `sign-blob` steps are unchanged.

## Fixed

- **The proxy forwards the enforcement point's key only to the configured wardryx (#32).** The proxy still forwards the caller's `Authorization` header to wardryx, since it is the enforcement point's own key and wardryx needs it to bind the agent. What changes is where that header can go: the default transport dials only the configured upstream's host and port and refuses any other. The proxy keeps no key of its own.

## Changed since v0.4.1

Commits between the 0.4.1 tag and this release:

- #32, the proxy fix above.
- #33, `chore(deps): move agent-stack-go to the v2 module, v2.0.0`. The shared wire-type import moves to `github.com/TAIPANBOX/agent-stack-go/v2`. Nothing an operator sets or sees moves with it.
- #34, `ci(release): sign the image in the legacy format policy-controller reads`. The image sign step adds `--new-bundle-format=false --use-signing-config=false`, with a comment above it.
- agent-stack-go pins v1.2.0 (#30) and v1.3.0 (#31), before the v2 move.
- README: the install lines name the published image and tag (#29).

## Upgrade

Nothing to change in a deployment. Pull `ghcr.io/taipanbox/typryx:v0.4.2` in place of `v0.4.1`. The image size in the README is the 0.4.1 measurement and was not re-measured for this release.
