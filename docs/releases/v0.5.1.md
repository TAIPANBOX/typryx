# Typryx 0.5.1

A patch release on the 0.5 surface. The `typryx` image, `ghcr.io/taipanbox/typryx`, is built with Go 1.27.3, which fixes GO-2026-6809 in `crypto/x509`. Version 0.5.0 was built with Go 1.27.2. Nothing on the wire, in the journal or in the training log changed, and there is no new variable, route or format.

## Upgrade

Nothing breaks, and an existing run needs no edit. Pull `ghcr.io/taipanbox/typryx:v0.5.1` in place of `v0.5.0`. The configuration and the stored state are the same. The image size in the README is the 0.4.1 measurement and was not re-measured for this release.

## Changed since v0.5.0

Commits between the 0.5.0 tag and this release:

- #37, `build: Go 1.27.3 for GO-2026-6809 in crypto/x509`. The `go.mod` toolchain, the CI and release `go-version`, and the Dockerfile Go version move from 1.27.2 to 1.27.3, so `govulncheck` is clean again and the published image carries the fixed standard library. No source file of typryx changes.
- #36, `chore(deps): bump agent-stack-go to v2.0.1`. A dependency bump that changes `go.mod` and `go.sum` only. The upstream release changes no Go code.
- README: the install lines name the v0.5.1 image and tag, and `components.json` lists the tag's date in the distribution field.

No other commit lies between the 0.5.0 tag and this release.

## Not proven

- Whether GO-2026-6809 was reachable from typryx's own code under Go 1.27.2 was not measured. The bump removes the question rather than answering it.
- The release and image jobs run only on the tag push.
- The Go version of the shipped binary is read with `go version` from the published image after the tag is pushed.
